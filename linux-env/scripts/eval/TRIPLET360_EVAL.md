`triplet_bank.py` consumes the authoritative held/train registries and their SHA-bound dual projection. The sealed held bank has20 actual layouts and60 cases; replacement identities remain explicit. The legacy integer `seed` is only a unique case key (`layout_seed*10 + RGB index`). Actual layout_seed/repeat controls flow noise across prompts/checkpoints. Four15-case chunks each contain five complete RGB layouts. One canonical recorded RED camera/state input per layout is shared by all CPU prompt probes. Reuse closure-diagnostics' existing colour RPC probe and generic analyzer; do not create another loader.

`triplet_reset.py` initializes the fresh collector through its real `Collector.scene` recorded-replay branch: planning-scene clear, recorded physical restore,2 unrecorded scene barrier ticks and pose verification. This sets the actual production scene-clear/pose metadata without sampling. The opt-in suite is `triplet-heldout-20x3`; legacy reset/default behavior stays separate. Source/MCP gitlink, native pose, camera-tick, memory and ownership checks remain active. The private runtime must match candidate qualification sources before qualification. No model is loaded by the bank/reset tests.

Operational commands, registry/proof bindings and independent reviews are delivered on the Mac at roadmap-2026-11/phase3/3.3-eval/triplet360/.

Retained checkpoint completion: the producer retains all model saves and only the latest optimizer. For a historical TRIPLET save whose optimizer training_step marker was pruned, acceptance requires native last STRICTLY newer than that save, the matching triplet artifact SHA, plus unchanged actual-processor admission and full stable source/target bundle SHA. A latest-save missing its marker still refuses. Other families keep their optimizer-marker requirement. The receipt preserves training_step_present=false and records the historical completion evidence; it never fabricates an optimizer marker.

The operational controller requires an explicit selected-checkpoint lead authority (gpu_start_authorised:true plus gpu_step/source message). The qualification plan must carry the selected --step too, even though its native argv is model-free. Legacy5k pre-authorisation is refused by default; checkpoint admission and CPU probe bindings remain mandatory.
