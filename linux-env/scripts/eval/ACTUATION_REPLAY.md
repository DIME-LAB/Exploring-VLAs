Actuation replay is a SIM-only diagnostic before model scoring. Replays start at the post-normalization action boundary: exact recorded degree-valued dataset labels go through the production SO101ROS2 backend, its degree-to-radian conversion and clamps, actual ROS publishers, JTC, mock references and native Isaac physical drives. No model or policy RPC is used. Camera and model preprocessing fidelity are separate checks.

The positive-duration baseline uses the existing1/30s single-point trajectory. Candidate `--actuation-mode immediate` sets only this backend instance's action_duration_s to0, so the native backend emits an immediate position waypoint. It preserves parsing, absolute units, clamps, joint order, publisher identity and normal homing. The default mode remains native. Nothing in a real-hardware deployment changes; physical servos require their own explicit design and validation decision. Immediate mode requires a sim clock and the parent requires the owned domain92 native physical deployment.

Humble's native `joint_trajectory_controller/src/trajectory.cpp` starts a zero-header trajectory at its first sample. A future first point is interpolated from the old state, while a zero-time single point is immediately its endpoint. Replacing a future point every simulation tick can therefore repeatedly restart interpolation. The replay tests this mechanism; it is not accepted from source reading alone.

`training_starts.py prepare` seals five accepted training layouts and exact measured starts, with actual receipt colours. `prepare_replay.py` extracts one accepted normal episode per colour (530000–530002), exact action labels including their recorded DART offsets, measured states and drive targets, checking full source SHA. Parent `action_replay.py` uses normal homing, aligns the ROS controller reference, then the reviewed native exact-state/body restore with zero velocities. Child `replay_client.py` runs through production pixi activation and the same 30Hz PacingClock/TickSchedule; its cameras are empty because this test isolates actuation. Publisher witnesses preserve actual radian messages, command indices and point times. Parent records received commands, controller desired/actual, mock references, physical targets/states, outcomes and videos. Source/config/reset/cap proofs are retained.

Run via the existing owned diagnostic runner with `--training-start-root`, `--replay-source`, and `--actuation-mode native|immediate`. It starts only instance2/domain92/GPU0, requires a new output, stops only its own process groups and always performs instance-scoped cleanup. Announce START/STOP for each window. Baseline, immediate-mode transport calibration and three full immediate replays are separate windows.

Acceptance: drive-target fidelity is primary. Freeze one transport lag from independent publisher→JTC desired→applied-target calibration, then compare to exact recorded targets at float32 precision. Do not choose a best lag to make replay pass. Report raw lag0–3 scans separately. Require zero missed dispatch slots, cap30 read-back, correct epochs and no camera/clock/RPC faults. Pre-closure arm state checks additionally require per-joint RMS<=max(0.5deg,2×training tracking RMS), max<=max(2deg,2×training max), TCP RMS<=2mm/max<=5mm. Gripper and contact-phase errors, grasp and placement are reported separately because cross-host contact dynamics can diverge. None of these secondary loose state limits can substitute for target fidelity. Immediate mode must show a clear target-delivery improvement over the positive-duration baseline.

The actual-RCLPy publisher API and restoration test passes on CPU/domain100, and the opt-in hardware guard has unit coverage. Live replay fidelity and independent result review remain pending. All previous Phase3 closed-loop scores must be interpreted as observations from an actuation path defective under the simulation-time deployment; their physical events remain recorded, but they do not measure qualified model ability.

`run_episodes.py --sim-time --eval-actuation immediate` opts the actual persistent policy client into the same immediate native waypoint adapter. Both dry-run and live child commands carry `--eval-actuation=immediate`; every episode and client result records the selected mode and the effective zero duration. Defaults remain native. This is the **deployment-realism, actuation v2** arm: the independent transport calibration observed variable 2–4 simulation-tick latency, so it does not pass the stricter collector-native target-fidelity gate. The actual FIFO10 replay placed 3/3 training episodes with no missed slots; the positive-duration actual FIFO10 baseline placed 0/3. A separate main-thread baseline placed 3/3, establishing scheduling/phase dependence rather than universal inability of JTC to execute these actions.

`run_actuation_window.py` owns one new-output MAIN30 RTC-on bank-v1 window, retains failed attempts as outcomes, advances without retrying an attempted seed, and reserves cleanup time before its required UTC deadline. It retains eager inference, 100 non-actuating warmup actions, 30 simulation Hz, 50-action chunks and 10-action observation cadence. Source hashes and the scene-bank SHA are recorded. Prior scores remain immutable and labelled defective-path observations. Native held-tick primary evaluation remains a separate, pending qualification.
