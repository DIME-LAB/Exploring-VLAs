### SIGBUS mitigations (partial — see open bug)
- **`OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES`** in `/tmp/run_core_real.sh`: macOS Foundation refuses fork() in a Tk-loaded multi-threaded process; `subprocess.Popen` from `_real_connect_worker` triggered the abort. Setting the env var lets fork+exec proceed.
- **Topic-swap subscriptions orphaned, not destroyed**: `_safe_orphan_subscription` replaces 4 `destroy_subscription` callsites (objects_sub, bbox_sub, _drop_sub) where the executor's spin thread races the destroy and SIGBUSes. Memory grows by one stale sub per topic-switch (bounded). Temp subs (cup-pose / lego-pose refresh) keep using `destroy_subscription` since those are per-button-click and would actually leak meaningfully.

## SIGBUS — root cause + fix (RESOLVED 2026-04-27)

**Symptom (was)**: control_gui crashed with **SIGBUS / exit code -10** when the notebook tab activated **Quickstart** or **Real Test**. `select_tab: switched to 'Quickstart' (idx=3)` was the last log line before the process died.

**True root cause** (font hypothesis was wrong): macOS crash report `~/Library/Logs/DiagnosticReports/python3.12-2026-04-27-053838.ips` showed:
- `EXC_BAD_ACCESS / SIGBUS / EXC_ARM_DA_ALIGN at 0x000000000bad4007`
- Faulting thread: `com.apple.main-thread`
- Stack symbols: `IIOReadPlugin::callInit...`, `handle_error(png_struct_def*, char const*)`, `handle_warning(png_struct_def*, char const*)`

**Mechanism**: Quickstart and Real Test tabs were the *only* tabs with Apple Color Emoji glyphs in button labels (🔄 / ▶ / ⏸ / ⏮). Apple Color Emoji ships PNG-bitmap glyphs (sbix / CBDT tables); CoreText routes those through ImageIO/libpng on first paint. ImageIO state had been corrupted earlier by control_gui's auto-Connect spawning subprocesses from a daemon thread — `posix_spawn` + `OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES` muzzle the Foundation-level abort but **don't protect ImageIO's internal pool**. Net result: every other tab rendered fine (vector glyphs only), but the moment ttk laid out the emoji-bearing buttons on first activation, libpng's error handler dereferenced corrupted state → unaligned PC → SIGBUS.

**Fix**: stripped 🔄 / ▶ / ⏸ / ⏮ from button labels in `_build_quickstart_tab` (control_gui.py:3584/3610/3615/3620) and `_build_real_test_tab` (control_gui.py:4102/4127/4140/4217). Also moved tk.Listbox font from `'TkFixedFont'` (named alias) to `'Menlo'` (concrete) at three sites — hygiene improvement, not bug-fix.

**Deeper-root follow-up (NOT done in this commit)**: the underlying ImageIO/CoreGraphics-state-corruption from `subprocess.Popen` in `_real_connect_worker`'s daemon thread will re-bite the moment any code in this process loads a PNG/JPEG asset (icon, image button, etc.) after auto-Connect runs. Two clean fixes when this surfaces again: (a) move auto-Connect dispatch onto the Tk main thread before `mainloop()` starts, OR (b) launch jsr_write + trajectory_shim from the launch file directly so control_gui never forks a subprocess. Today's strip-the-emojis fix avoids the codepath entirely on the active UI surface, which is sufficient for shipping 6-07.
